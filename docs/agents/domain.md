# Domain docs

## Before exploring code

Read root `GLOSSARY.md` and ADRs in `docs/adr/` relevant to the task.
This repo uses a single-context layout.

Proceed silently when these files are absent. `/domain-modeling`
creates them lazily when terminology or decisions resolve.

## Vocabulary

Use glossary terms in issues, proposals, hypotheses, and tests.
Reconsider unfamiliar terms; note genuine gaps for `/domain-modeling`.

## Decisions

Explicitly flag proposals that contradict an existing ADR,
identifying the ADR and why the decision deserves reconsideration.
